前言

为什么写这本书#

很多人学设计模式的方式是这样的：先记住一个名字，再看一张类图，然后读一段示例代码。学完 23 个，回到自己的项目里，却不知道什么时候该用哪一个；或者反过来，到处都想用，把十行能写完的事情拆成了五个类。

问题不在模式本身，而在顺序。设计模式是前人面对反复出现的困难时总结出的做法。脱离了那个困难，模式就只剩下一个名字和一种结构，看起来很高明，却说不清它解决了什么。

所以这本书把顺序倒过来：不从模式的名称开始，而从它要解决的问题开始。

每一章是怎样展开的#

除了第一部分的基础章节和第五部分的语言章节，每个模式章都沿着同一条路线走：

  1. 一个具体的小任务：图书馆的还书提醒、租房网站的搜索、温室的温度传感器……每章换一个场景，避免所有例子都是“动物会叫”。
  2. 最简单的写法：先用普通的 Python 把它写出来。这一步常常就是好代码，书里会明确这样说。
  3. 需求发生变化：变化是具体的，比如“管理员想先演练一遍”“第二家供应商只提供 JSON”。
  4. 原来的写法在哪里变难：不是抽象地说“不够灵活”，而是指出具体的错误。大多数章节里，这个错误都有一个测试能稳定地复现。
  5. 新的设计：先说清楚要把什么放到哪里，再给出 GoF 的模式名称和意图。
  6. 代价与边界：多了什么，难在哪里，以及什么时候不该用。
  7. Python 角度：同样的问题，Python 有没有更轻的写法？很多时候有：一个函数、一个字典、一个数据类。
  8. 小结与练习：练习的答案通常不是“用这个模式”，而是“在这种情况下，要不要用”。

代码#

书中所有代码都可以运行，只用 Python 3.11 及以上版本的标准库，不需要安装任何第三方包，也不需要网络。

每段代码都原样出自仓库 examples/ 目录里的文件，每章正文中给出的输出都有测试核对。读到某一章时，可以打开对应的示例文件，改一改参数，再运行测试，看看哪些行为变了。这比只读文字有用得多。

这本书不讲什么#

  • 不讲架构。 微服务、分层、领域驱动设计这类话题，关心的是整个系统怎样划分。本书讨论的是函数、类和对象之间的设计，范围小得多。
  • 不追求凑齐模式。 GoF 的 23 种模式都会讲到，但第六部分的贯穿案例只用到了其中几种。这是有意的：模式是对困难的回应，不是需要集齐的清单。
  • 不把 GoF 的类图当成 Python 的标准答案。 GoF 的书写于 1994 年，示例语言是 C++ 和 Smalltalk。Python 的函数是对象，类本身可以当参数传递，很多模式在 Python 里有更简单的形态。每章的“Python 角度”专门讨论这一点。

读者需要什么#

能读懂变量、条件判断、循环、函数和最基本的类就够了。遇到 dataclass、Protocol、上下文管理器这类稍进阶的工具，书中会在第一次用到时解释，第五部分还会专门回顾。

怎样读#

第一部分建议按顺序读，它建立了全书的思考方法：先看数据，再看处理；先问“简单写法够不够”，再问“要不要模式”。之后的模式章可以按需要跳着读，每章开头都有一个问题，看一看是不是你正在遇到的。第六部分最好放在最后读，它把前面的选择放回一个完整的小项目里，并演示怎样比较两种都能工作的设计。

读完之后，希望你记住的不是 23 个名字，而是一个习惯：写下一个设计之前，先能说出它要应对的变化是什么，以及为什么现在就值得为它付出代价。
